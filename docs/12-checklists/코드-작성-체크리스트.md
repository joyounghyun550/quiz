# 코드 작성 체크리스트

📍 **위치**: [홈](../00-README.md) > [체크리스트](../12-checklists/) > 코드 작성 체크리스트

---

새로운 기능을 구현하거나 코드를 작성할 때 다음 체크리스트를 확인하세요.

---

## 1. Next.js 렌더링 전략

- [ ] Server Component가 기본값임을 인지하고 있는가?
- [ ] 'use client'가 정말 필요한가? (React 훅, 브라우저 API, 상호작용)
- [ ] Client Component를 트리의 리프 노드에 배치했는가?
- [ ] 데이터 페칭을 Server Component에서 수행하고 있는가?
- [ ] 무거운 컴포넌트는 Dynamic Import를 고려했는가?
- [ ] Suspense와 loading.tsx를 활용하여 로딩 상태를 처리했는가?

---

## 2. TSDoc 및 주석 작성

### 컴포넌트

- [ ] 컴포넌트에 JSDoc 주석을 작성했는가?
- [ ] 컴포넌트의 용도와 주요 기능을 설명했는가?
- [ ] @param으로 Props를 설명했는가?
- [ ] @example로 사용 예시를 제공했는가?
- [ ] @see로 관련 타입을 참조했는가?

### Props 타입

- [ ] Props 타입을 별도 `.type.ts` 파일로 분리했는가?
- [ ] 각 필드에 설명 주석을 작성했는가?
- [ ] 필수/옵션 여부가 명확한가? (`?` 표시)
- [ ] 선택적 Props에 @default로 기본값을 명시했는가?
- [ ] 콜백 함수의 파라미터를 설명했는가?
- [ ] 복잡한 Props는 @example로 사용 예시를 제공했는가?

### 커스텀 훅

- [ ] 훅의 용도와 주요 기능을 설명했는가?
- [ ] @param으로 파라미터를 설명했는가?
- [ ] @returns로 반환값의 각 필드를 설명했는가?
- [ ] @example로 실제 사용 예시를 제공했는가?
- [ ] 복잡한 훅은 내부 함수에도 주석을 추가했는가?

### API 함수

- [ ] API 함수의 용도를 명확히 설명했는가?
- [ ] @param으로 파라미터를 설명했는가?
- [ ] @returns로 반환값을 설명했는가?
- [ ] @throws로 발생 가능한 에러를 문서화했는가?
- [ ] @example로 에러 처리 방법을 포함한 사용 예시를 제공했는가?

### 유틸리티 함수

- [ ] 함수의 용도를 명확히 설명했는가?
- [ ] @param, @returns를 작성했는가?
- [ ] @example로 사용 예시를 제공했는가?

---

## 3. 코드 구조 및 스타일

### Import

- [ ] Import 순서를 준수했는가? (React → 외부 라이브러리 → Shared → Features → Layouts → Assets)
- [ ] 타입 import는 `import type` 구문을 사용했는가?
- [ ] 복잡한 파일은 주석 블록으로 섹션을 구분했는가?

### 컴포넌트 구조

- [ ] 파일 상단에 'use client' 지시어를 추가했는가? (필요시)
- [ ] 상수는 컴포넌트 외부에 선언했는가?
- [ ] Hooks는 컴포넌트 최상단에 배치했는가?
- [ ] 함수 → useEffect → 렌더링 순서를 따랐는가?
- [ ] 복잡한 컴포넌트는 섹션 구분 주석을 사용했는가?
- [ ] Default export를 사용했는가?

### 네이밍

- [ ] 폴더명은 kebab-case를 사용했는가?
- [ ] 컴포넌트 파일명은 PascalCase를 사용했는가?
- [ ] 타입/훅/API/유틸 파일은 kebab-case를 사용했는가?
- [ ] 변수/함수는 camelCase를 사용했는가?
- [ ] 상수는 UPPER_SNAKE_CASE를 사용했는가?
- [ ] 이벤트 핸들러는 `handle + 동작명` 형식인가?

---

## 4. 타입 안정성

- [ ] 모든 함수에 타입을 정의했는가?
- [ ] any 타입 사용을 최소화했는가?
- [ ] Props 타입을 별도 파일로 분리했는가?
- [ ] API 응답 타입을 정의했는가?

---

## 5. 폴더 구조 및 레이어 의존성

- [ ] 올바른 폴더에 파일을 배치했는가? (features, shared, layouts 등)
- [ ] 레이어 의존성을 준수했는가? (app → layouts → features → shared)
- [ ] index.ts를 통해 Public API를 관리했는가?
- [ ] features 간 직접 import를 하지 않았는가?

---

## 6. 성능 최적화

- [ ] 불필요한 리렌더링을 방지했는가? (useCallback, useMemo)
- [ ] 무거운 컴포넌트는 Dynamic Import를 고려했는가?
- [ ] 이미지는 Next.js Image 컴포넌트를 사용했는가?
- [ ] 리스트 렌더링 시 key prop을 올바르게 설정했는가?

---

## 7. 에러 처리

- [ ] API 호출 시 try-catch로 에러를 처리했는가?
- [ ] 에러 발생 시 사용자에게 적절한 메시지를 표시하는가?
- [ ] error.tsx 파일을 활용하여 에러 UI를 제공했는가?

---

## 8. 접근성 (Accessibility)

- [ ] 버튼과 링크에 적절한 aria-label을 제공했는가?
- [ ] 이미지에 alt 속성을 추가했는가?
- [ ] 키보드 네비게이션이 가능한가?
- [ ] 의미있는 HTML 태그를 사용했는가? (semantic HTML)

---

## 9. Git 커밋

- [ ] 의미있는 커밋 메시지를 작성했는가?
- [ ] 하나의 커밋에 하나의 논리적 변경사항만 포함했는가?
- [ ] 불필요한 파일(node_modules, .env 등)을 커밋하지 않았는가?
